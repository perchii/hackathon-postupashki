# Хакатон «Поступашки» — маркетинговая аналитика

Цель проекта — понять, какие маркетинговые активности связаны с продажами, какие данные уже позволяют это оценивать и какую систему измерения нужно построить для дальнейшего расчёта ROMI и принятия решений по рекламному бюджету.

## Данные

На старте есть два основных сырых блока:

1. `base` — данные о покупках: пользователь, сумма, курс, время покупки.
2. `Marketing History` — собранная история внутренних и внешних Telegram-упоминаний и маркетинговых событий.

> В публичный репозиторий не добавляем персональные данные. Если исходный `student_id` потенциально чувствителен, перед публикацией его нужно обезличить или удалить.

## Ближайшие аналитические блоки

- EDA покупок: качество данных, заказы, повторные покупки, пакеты, динамика и аномалии.
- EDA Marketing History: типы событий, каналы, кампании, скидки, запуски, пропуски и качество разметки.
- Связка маркетинга с продажами: временные лаги, анализ до/после, атрибуция и ограничения причинных выводов.

## Ключевой принцип

Разделяем выводы на три уровня:

- **KNOW** — что напрямую наблюдаем в данных.
- **ESTIMATE** — что оцениваем моделями, атрибуцией или статистикой.
- **CANNOT KNOW NOW** — что невозможно восстановить исторически из-за отсутствующих данных и что необходимо логировать в будущем.

Историческое совпадение маркетингового события и роста продаж не равно доказанной причинности.

## Воспроизводимость

1. Установить Python 3.11+.
2. Создать виртуальное окружение.
3. Установить зависимости:

```bash
pip install -r requirements.txt
```

4. Положить обезличенные исходные данные в `data/raw/`.
5. Запускать ноутбуки из `notebooks/`.

## Команда

Распределение задач фиксируется по фактическим аналитическим блокам, а не жёстко по ролям. Все результаты должны быть воспроизводимы из файлов репозитория.
